## 1. 完成范围

- 新增 `POST /api/v1/ai/advisor` AI 选片顾问接口，要求登录并具备 `ai:chat` 权限。
- 请求问题使用 DTO 和 Bean Validation 校验，空问题或超过 1000 字符返回 HTTP 400。
- AI 请求在处理前调用阶段 3 的 `AiUsageLimitService.consume(userId)`，分钟限流和每日额度继续生效。
- 新增提示注入、敏感凭据和控制字符检查；拒绝事件只记录短原因标签，不记录用户原文。
- 定义 `LlmClient` 抽象，提供默认 `FakeLlmClient` 和 OpenAI 兼容 HTTP 实现。
- OpenAI 兼容实现支持后端 API Key、模型、超时、重试、温度和最大输出配置，也可连接 Ollama 的 `/v1` 兼容端点。
- 在 `resources/prompts` 中维护版本化意图提取和推荐解释提示模板。
- 本地解析类型、排除类型、片长、评分、年份和主题关键词；模型意图与本地结果合并，本地明确条件优先。
- 每部电影生成规范文本，结合 SQL 约束过滤、文本匹配、User-CF、评分和热度进行融合排序。
- 模型只能从后端候选集选择电影；响应前逐项回查候选 `movieId`，删除重复或虚构 ID。
- 模型超时、网络失败、非法 JSON、无效输出或有效推荐不足时，降级为本地检索结果，不使整个接口失败。
- AI 调用审计记录供应商、耗时、候选数、结果数和状态，不记录问题、提示词、Token 或 API Key。

## 2. 接口

```text
POST /api/v1/ai/advisor
Authorization: Bearer <access-token>
Content-Type: application/json

{
  "question": "想和父母看两个小时以内的温馨喜剧，不要恐怖片，评分高一些"
}
```

响应数据包含：

- `answer`：模型总结或降级提示。
- `intent`：后端最终采用的结构化条件。
- `recommendations`：真实片库电影、理由、匹配条件和详情路径。
- `aiGenerated`：推荐解释是否由模型有效生成。
- `degraded`：本次是否发生模型或输出降级。
- `provider`：`fake` 或实际 OpenAI 兼容模型标识。

## 3. 检索与排序

当前阶段采用适合课程项目数据规模的轻量混合 RAG，不引入额外向量数据库：

```text
finalScore = 0.40 * textSemanticScore
           + 0.25 * constraintMatch
           + 0.20 * userCfScore
           + 0.10 * normalizedRating
           + 0.05 * popularityScore
```

SQL 先执行片长、评分、年份、类型和排除类型过滤，再在最多 200 条候选上计算规范文本匹配与融合分数，默认向模型提供 Top 8。此实现已经形成完整 RAG 闭环；后续数据规模增大时可在 `HybridMovieRetriever` 内替换或叠加 embedding 检索，不需要改变控制器契约。

## 4. 环境变量

```text
LLM_PROVIDER            默认 fake；真实模型使用 openai-compatible
LLM_BASE_URL            默认 http://localhost:11434/v1
LLM_API_KEY             可空；只在后端进程环境提供
LLM_MODEL               默认 qwen2.5:7b
LLM_TIMEOUT_SECONDS     默认 20
LLM_MAX_RETRIES         默认 1
LLM_MAX_OUTPUT_TOKENS   默认 800
LLM_TEMPERATURE         默认 0.2
AI_RETRIEVAL_LIMIT      默认 8，后端限制为 3~20
```

默认 Fake 模式不访问网络，适用于本地开发和 CI。连接 Ollama 时可保持 API Key 为空；连接需要鉴权的 OpenAI 兼容服务时必须通过环境变量注入 Key。

## 5. 安全与降级行为

| 场景 | 结果 |
| --- | --- |
| 未登录 | HTTP 401 |
| 缺少 `ai:chat` | HTTP 403 |
| 问题为空或超过 1000 字 | HTTP 400 |
| 提示注入或疑似凭据 | HTTP 400，并记录 `AI_INPUT` 拒绝事件 |
| AI 额度用尽 | HTTP 429，并沿用阶段 3 审计 |
| 模型超时、5xx、429 或网络错误 | 按配置重试后返回本地降级结果 |
| 模型 JSON 无效 | 返回本地降级结果 |
| 模型返回候选外 `movieId` | 丢弃该项，不向客户端返回 |
| 有效模型推荐不足 | 整组模型结果作废，返回本地 Top 结果 |
| 本地无候选 | 返回空推荐和放宽条件提示 |

## 7. 已知边界与下一阶段

- 当前语义分数采用规范电影文本的轻量关键词匹配，尚未持久化 embedding；数据量或召回要求提升后可增加 embedding 和余弦相似度。
- 当前接口是单轮问答，不保存 AI 会话，因此不存在跨用户会话读取面；阶段 5 如增加持久会话，查询必须同时带 `conversation_id + user_id`。
- Fake 模型用于可重复测试，不代表真实模型质量；真实模型演示需单独配置并验证服务兼容 `response_format=json_object`。
- 阶段 5 前端应把理由按纯文本渲染，不使用未经处理的 `v-html`，并明确展示 `degraded`、429 和失败重试状态。
