# 电影推荐系统阶段 3 完成交接文档

> 项目路径：`D:/个人项目/movie_recommendation_systems`
> 完成日期：2026-09-20
> 主题：强化令牌、登录限制、AI 额度与安全审计

## 1. 完成范围

- Access Token 默认有效期缩短为 15 分钟，JWT 增加服务端会话 ID。
- 新增 HttpOnly Refresh Cookie，默认 7 天；刷新时轮换令牌与会话。
- Refresh Token 仅以 SHA-256 哈希入库，不在 JSON 响应、日志或审计数据中出现。
- JWT 过滤器同时校验用户状态和服务端会话；退出、刷新、改密、禁用或注销后旧 Access Token 立即失效。
- Refresh Token 重放会撤销该用户全部会话。
- 前端移除 `localStorage` 令牌与角色，Access Token 只保存在内存；页面刷新时通过 HttpOnly Cookie 静默续期。
- Axios 对并发 401 共享一次刷新请求，成功后只重放原请求一次。
- 新增登录失败限制：默认同一用户名和 IP 在 15 分钟内失败 5 次后限制 15 分钟。
- 新增可供阶段 4/5 AI 接口调用的用户级分钟限流和每日额度服务。
- 记录登录、刷新、退出、会话撤销、权限拒绝、管理员用户操作和 AI 限流安全事件。
- 新增管理员审计事件分页接口，要求 `ADMIN` 角色和 `audit:read` 权限。

## 2. 新增接口

```text
POST /api/v1/auth/refresh
POST /api/v1/auth/logout
GET  /api/v1/admin/audit-events?current=1&size=20
```

登录和刷新响应返回 `accessToken`、`tokenType`、`expiresIn`，Refresh Token 仅通过 `Set-Cookie` 下发：

```text
HttpOnly; SameSite=Strict; Path=/api/v1/auth
```

生产配置默认要求 `Secure` Cookie。开发环境通过 Vite 同源代理访问后端，可使用非 Secure Cookie。

## 3. 数据库迁移

Flyway `V3__add_security_sessions_and_audit.sql` 新增：

- `refresh_token`：用户、会话 ID、令牌哈希、过期、撤销、轮换关系和使用时间。
- `security_audit_event`：事件类型、结果、操作者、受控主题、IP、请求 ID、元数据和时间。
- `ai:chat` 权限，并授予 USER、ADMIN 角色。

不要修改已执行的 V1、V2。已有数据库部署前先备份，再由 Flyway 执行 V3。
上线 V3 后，旧版没有会话 ID 的 Access Token 会失效，用户需重新登录一次。

## 4. 安全行为

| 场景 | 结果 |
| --- | --- |
| Access Token 过期 | 前端使用 Refresh Cookie 轮换后重试一次 |
| 主动退出 | 当前会话撤销，Cookie 清除，旧 Access Token 立即无效 |
| 修改密码 | 用户全部会话撤销 |
| 管理员重置密码、禁用或注销用户 | 目标用户全部会话撤销 |
| Refresh Token 重放 | 用户全部会话撤销并记录拒绝事件 |
| 登录失败达到阈值 | 返回 HTTP 429 并记录 `LOGIN_RATE_LIMIT` |
| AI 分钟或每日额度用尽 | 返回 HTTP 429 并记录 `AI_RATE_LIMIT` |
| 未登录或权限不足 | 返回 401/403 并记录安全事件 |

审计元数据只允许服务端生成的短标签，不记录密码、Token、Cookie、API Key 或用户原始 AI 问题。

## 5. 环境变量

```text
JWT_SECRET                         必填，至少 32 个 UTF-8 字节
JWT_EXPIRATION_MS                  默认 900000
JWT_REFRESH_EXPIRATION_SECONDS     默认 604800
JWT_REFRESH_COOKIE_SECURE          开发默认 false，生产默认 true
LOGIN_MAX_ATTEMPTS                 默认 5
LOGIN_WINDOW_SECONDS               默认 900
LOGIN_LOCK_SECONDS                 默认 900
AI_REQUESTS_PER_MINUTE             默认 10
AI_REQUESTS_PER_DAY                默认 100
```

## 7. 已知边界与下一阶段

- 登录失败计数和 AI 额度当前是单实例内存实现，适合当前单机课程项目；多实例或需要重启后保持计数时应迁移到 Redis，并使用原子计数/过期。
- `security_audit_event` 当前由管理员 API 查询，后续可增加事件类型、时间和操作者筛选。
- 阶段 4/5 的 AI 控制器必须在调用模型前执行 `AiUsageLimitService.consume(userId)`，并使用 `ai:chat` 方法级权限。
- 生产必须使用 HTTPS、`JWT_REFRESH_COOKIE_SECURE=true`，并让前端与 API 保持同站部署；若必须跨站部署，需要重新评估 SameSite 和 CSRF 防护。
