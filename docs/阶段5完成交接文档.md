## 7. 当前运行状态和必须收尾项

截至交接时：

```text
前端：http://127.0.0.1:5173
AI 页面：http://127.0.0.1:5173/ai-advisor
后端：http://localhost:8080
后端健康接口：HTTP 200
旧详情路径别名：HTTP 200
```

当前运行实例存在需要在新对话优先处理的环境问题：

1. 多轮验收后，MySQL 数据查询出现持续阻塞。`GET /api/v1/health` 仍返回 200，但依赖数据库的电影查询会超时。
2. 后端 JVM 线程栈显示 Tomcat 工作线程已经空闲；本机 MySQL 服务仍是 Running，3306 可连接，但应用的 10 个 MySQL 连接均处于 Established。需要重启 MySQL 或进一步检查数据库锁/事务。
3. 当前会话无 Windows 服务控制权限，`Restart-Service MySQL` 被拒绝；需要在管理员终端中重启 MySQL。
4. 当前后端是旧 JAR 运行实例，尚未加载本阶段的 `/movie/{id}` 后端修复。前端别名已保证旧实例可用。
5. 后端进程中的 DeepSeek Key、数据库密码和 JWT Secret 不可从当前 shell 安全继承。停止后端前先按安全方式重新准备这些环境变量。
6. 最后两次因数据库阻塞而中断的重复验收可能留下 `s5_` 或 `s5f_` 前缀临时账号。数据库恢复后应通过管理员 API 或受控 SQL 查询并删除这些账号。不要删除其他用户。

建议的收尾顺序：

```text
1. 在管理员终端重启 MySQL。
2. 查询并清理仅以 s5_ / s5f_ 开头的临时用户。
3. 安全注入 DB_PASSWORD、JWT_SECRET 和 DeepSeek 环境变量。
4. 停止旧后端实例。
5. 执行 mvn.cmd -q -DskipTests package。
6. 启动新 JAR。
7. 检查 /api/v1/health、电影查询和 /api/v1/ai/advisor。
```

## 10. 重要边界

- 当前 AI 顾问仍是单轮请求，不保存 AI 会话。
- 当前 RAG 仍使用 SQL 过滤、文本匹配、User-CF、评分和热度融合，没有独立向量数据库。
- AI 分钟限流和每日额度仍是单实例内存实现。
- 生产部署必须使用 HTTPS，并设置 `JWT_REFRESH_COOKIE_SECURE=true`。
- 不要把 DeepSeek API Key、数据库密码、JWT Secret、Token、Cookie 或临时凭据文件提交到 Git。
- 工作区包含阶段 2 至阶段 5 的大量未提交改动，新对话不得重置或覆盖这些已有修改。
